# 古文英译刷词 · 网页体验版

Windows 上用来试玩 iOS 版的同一套题库与同一套流程。**双击 `index.html` 即可打开**，不需要装任何东西、不需要联网、不需要服务器。

## 它是什么

iOS 版（`ios/GuwenApp/`）只能在 macOS 模拟器或 iPhone 上跑。这一版是把 SwiftUI 的核心页（选择题 / 答案）与错题本，用 HTML + CSS + 原生 JS 逐行复刻出来的等价物，另外**多了一块 iOS 版没有的能力：按篇刷题**（目录 → 篇详情 → 通读 / 逐句刷）：

| 复刻对象 | 对应实现 |
|---|---|
| `TermLocator` | `termRanges()` / `markTerm()`，多出现处全部加下划线 |
| `Scheduler` | `pickRound()`，同一套 new/learning/due 抽样规则 |
| `ProgressStore` | `localStorage`，键名带数据版本号，题库更新自动迁移 |
| `Theme.swift` | CSS 变量，浅色 `#F5E6D3` / 深色 `#2A211A` 与 iOS 完全一致 |
| 篇章索引（iOS 没有） | `DATA.works`，30 篇 / 823 句，来自 `data/course_cards_v2.jsonl` |

题库就是仓库里的 `data/word_cards.jsonl` + `data/sentence_cards.jsonl` 经人工校订后的 1,515 张可出题卡，**与 iOS 版同源**，不是另做的样例数据。

## 怎么玩

1. 首页点「开始一轮」→ 20 道选择题，点选项即判分并当场换页（无等待动画）
2. 答案页从上到下是：选项（**绿勾 = 正确，红叉 = 你选的错项**）→ 英译 → **白话文** → 词义卡
3. **点英译里的任意一个英文单词**，会在词的上方弹出词典卡：音标、词性、中文释义，命中考点词时还会带「本句」义
4. 答案页右下角有「退出」，随时能中途离开（不用刷完 20 题）；页面上能「加入错题本」
5. 右上角 `⋯` 可切深色模式、切换发音方式、清除全部学习记录

### 点词发音

喇叭按钮走**三级回退**，任何一级失败都不报错、不卡住：

```
联网取有道真人音（1.2 秒内响） → 系统语音合成（离线可用） → 只显示音标
```

- 音标与释义来自内置的 `dict.js`（2,800 余词，只覆盖题库出现过的词，约 200 KB），**离线可用**。
- 真人音要联网，且会把**这一个单词**（不含上下文）发给有道。不想外发就 `⋯` → 发音 → 机器音。
- 断网时自动退系统语音，所以「地铁里点词没声音」不会发生；但机器音是合成声，不如真人音好听。
- 系统语音在微信内置浏览器里可能被禁用，这种情况下按钮点了没声——用 Safari 或主屏 App 打开正常。

### 按篇刷题

1. 底部「篇目」Tab（或首页「按篇刷题」卡片）→ 古文目录，按 **重点 / 次重点 / 普通** 三档分组
2. 每篇显示「已刷 x/y 句」和进度条；点行尾的「重点 ▾」可以把这篇改到别的档（只存本地）
3. 点进某一篇 → **整篇原文**按段排下来，没刷过的句子是灰的，刷过的转黑
4. 「通读」界面里点任意一句，弹出这句的白话、英译、以及这句里可考的词，可「单练这句」
5. 「刷题」界面里点「随机 20 题」，从**整篇题池**（= 这篇所有句题 + 词卡，滕王阁序 49 道）里抽 20 道，
   没答过的先出，上一轮出过的先避开 —— 连刷两轮不重样，几轮就把全篇铺满
6. 同一个界面还有「整篇一遍」，一次把全池打乱出完（49 题），适合考前过一遍

一轮 20 题答完直接进小结（默写已删掉）；小结页显示对了几题、本篇刷了多少句。

数据存在浏览器本地，刷新不丢；想重来就 `⋯` → 清除全部学习记录（篇目档位会保留）。

### 自己加一篇（本机篇目）

目录页右上角 `＋` → 三栏按「一句一行」粘**原文 / 白话 / 英译** → 保存。
保存后直接落到这篇的通读页，目录里那篇带一个「本机」小标。

- **原文里用空行分段**；白话、英译与原文的句数要一致，整栏留空表示不填。
- 英译里混进中文会被拦下（「第 3 句英译里还有中文，像是没译完」）—— 那种句子点词查不到东西。
- 加进来的篇目存在**这台设备的 localStorage**，换手机、清缓存就没了，也不会进题库。
- 能通读、点句看白话/英译、点词查词典；「刷题」出的是**句级四选一**，
  干扰项从题库里长度相近的英译里抽，答案页会如实标「干扰项来自题库里的其他篇目」。
- 没有人工校订的词卡（那 1,346 张是一句一句改出来的），所以自加的篇目**不出词义题**。
- 篇详情右上角 `⋯` 可以编辑 / 删除这篇。

要和内置那 30 篇同等对待（进题库、词卡、多设备可见），得走下面「新增一篇文章」的脚本入库，
再重新构建、重新发布。

## 它不是什么

- 不是正式发布的产品。它是验收用的体验版，方便在 Windows 上肉眼过一遍交互。
- 没有账号、没有云同步、没有排行榜，也不打算加。
- 真机装包（.ipa）需要 Apple 开发者签名，Windows 上做不了，所以才有这个网页版。

## 数据来源

`data.js` 由脚本生成，不要手改：

```bash
python scripts/build_web_demo_data.py
```

脚本做两件事：把 2,072 张源卡裁成 1,515 张可出题卡（凑不满 3 个干扰项的丢掉），
再把 `data/course_cards_v2.jsonl` 的 **30 篇 / 823 句**打包成 `DATA.works`。

`works` 的结构（短键是为了压体积）：

```js
{ t: "岳阳楼记", a: "范仲淹", lv: 1,     // 篇名 / 作者 / 档位 1重点 2次重点 3普通
  ps: [4, 6, 5, 5, 8, 1],                // 每段句数，段号由累加得出
  m: [["白话", 0], ["整段白话", 1]],       // 白话块，0=句级 1=段级
  s: [{ c: "原文", m: 0, e: "英译", w: ["w0001"], q: "s0001" }] }
```

几条硬约束，改脚本前先看：

- **段号不能靠 `para_index`**：`出师表` 那列跳号（缺 5、6），`爱莲说` 还有 OCR 变体（不然/不染）
  会让 prev/next 断链。一律用 `ps` 累加。
- **句子顺序 = `course_cards_v2.jsonl` 的文件顺序**，不要自己重排。
- **档位规则**：按篇内「考频五星卡片数」降序，前 10 篇重点、11–19 次重点、其余普通；
  同分看可出题数、再看篇幅。用户手动改档存在 `S.wlv`，只覆盖 `lv`，不动这个顺序。
- **`DATA_VERSION` 改了要同步改 `sw.js` 的 `CACHE`**，否则主屏 App 继续吃旧缓存。
  v6 → v7 有个一次性迁移（`loadState()` 里），卡片 id 没变，进度整份沿用。

新增一篇的办法：往 `course_cards_v2.jsonl` 追加连续行（`title` 写新篇名、
`para_index` 从 0 递增），重跑脚本，前端零改动。没有题的新篇也能进目录，通读可用，
刷题会显示「本篇暂无可练习题」。

图标由 `python scripts/make_icons.py` 生成（PIL 画「文」字 + 一道划线，
输出 180/192/512 与 maskable 四张），不要手改 PNG。

## 离线词库 `dict.js`

同样由脚本生成，不要手改：

```bash
python scripts/build_dict.py --ecdict /path/to/ecdict.csv
```

数据源是 [ECDICT](https://github.com/skywind3000/ECDICT)（MIT 许可）。全量 66 MB，
脚本只保留题库里出现过的词：**2,861 条 / 207 KB**，token 覆盖率 99.9%，
剩下 25 个查不到的基本是音译人名（`renxu`、`mengchang`、`chunshen`）和罕见复合词，
浮卡上显示「词典暂未收录这个词」。输出是一整串
`word\tipa\tpos\tgloss\tlemma` 纯文本，首次查词时才拆成 Map。

国内直连 GitHub 常不通，用镜像（单线程 45 KB/s 要 40 分钟，分 1 MB 段并发下载再拼接）：

```bash
curl -L https://ghfast.top/https://raw.githubusercontent.com/skywind3000/ECDICT/master/ecdict.csv -o ecdict.csv
```

三个硬约束（都是踩过的坑）：

- **切词正则必须两边逐字一致**：`index.html` 里的 `WORD_RE` 用于运行期切词，
  `build_dict.py` 里的同名正则用于构建期统计词表。不一致就会出现「页面上点得到的词，
  词库里根本没有」。`check_mobile.py` 会把两边的源串取出来比对。
- **词形还原在构建期做**（用 ECDICT 的 `exchange` 字段把 `demoted` 映射回 `demote`），
  运行期只做几条后缀兜底。运行期做 NLP 还原会给出更离谱的结果（`us → u`、`was → wa`）。
- **`translation` 里的换行是字面量 `\n` 两个字符**，不是真换行。直接 `split("\n")` 会把
  三行释义连成一句，浮卡上显示「使\nn. 条件\n[计] DOS 批处理文件…」。`clean_gloss()`
  先做反转义再切行，并去掉 `[计] [医]` 这类领域前缀。`check_mobile.py` 里有一条断言专门守它。

## 新增一篇文章

**正常用法：只说篇名，剩下的由 Agent 做完。** 原文、白话、逐句英译都不是用户该操心的事。

```bash
# 1) 写出逐句三栏（Agent 检索原文 + 写白话/英译），落到 _ingest/篇名.json
python scripts/ingest_work.py _ingest/篇名.json --dry-run          # 先看句数/段数/字数
python scripts/ingest_work.py _ingest/篇名.json --with-sentence-quiz  # 真写入 + 生成句级题

# 2) 把 scripts/build_web_demo_data.py 的 DATA_VERSION 加 1
python scripts/build_web_demo_data.py

# 3) 重新发布；手机端把 App 划掉重开一到两次
```

输入是一个 JSON（`title` / `author` / `source` / `sentences[{c,m,e,p}]`，
`c` 原文、`m` 白话、`e` 英译、`p` 段号）。同一段里多句共用同一句白话时，
脚本会自动标成「段级白话」，前端标签跟着变成「本段白话」。

脚本会拒绝三类脏数据：篇名与已有篇重复、某句缺原文/白话/英译、英译里还混着中文。

`--with-sentence-quiz` 生成的干扰项是从**别的篇**里按长度相近抽的，提示语标 `needs_manual`，
质量不如人工校订的那批 —— 但比「只有原文读不了」强，能立刻刷。

**已入库的示例**（2026-10-30 一次加的五篇，用来验证这条链路真的能跑）：

| 篇目 | 作者 | 句 / 段 / 字 |
|---|---|---|
| 兰亭集序 | 王羲之 | 17 / 4 / 390 |
| 归去来兮辞 | 陶渊明 | 31 / 5 / 399 |
| 项脊轩志 | 归有光 | 33 / 5 / 681 |
| 逍遥游（节选） | 庄子 | 39 / 6 / 805 |
| 滕王阁序 | 王勃 | 49 / 7 / 864 |

`check_mobile.py` 里 `NEW_WORKS` 就是这五篇的清单（篇名, 句数, 首句片段），
逐篇断言「句数对得上、首句在正文里、能出题」。以后加篇往里加一行，越攒越像回归测试。

拍图用 `python scripts/shot_work.py 滕王阁序`，出目录 / 通读 / 点句三张。

**分档**：新篇默认落在「普通」，因为档位是按篇内考频五星卡片数排的，新篇没有卡片记录。
要在目录里往前提，点篇目右侧的档位标签手动改（存进 `S.wlv`，不会被重建数据冲掉）。

## 装到 iPhone 主屏（当 App 用）

线上地址：<https://guwen-flashcards.app.workbuddy.host/?sharecode=5BOBJUPCXS>

iPhone 上用 **Safari** 打开（微信/QQ 内置浏览器不行，它们不支持添加到主屏），
点底部分享按钮 → **添加到主屏幕** → 命名「古文刷词」→ 添加。
之后从桌面图标打开就是全屏无地址栏，行为接近原生 App。

### 三个技术细节，都是踩过的坑

**1. `?sharecode=` 不能丢。**
这个托管地址对子资源有校验：第一次带 sharecode 访问时服务端下发
`__wb_rsc` cookie（30 天），之后 `data.js` / `manifest` / 图标才放行；
不带 sharecode 直接请求子资源一律 403。所以：

- `manifest.webmanifest` 里**故意不写 `start_url`**。写了 `./index.html` 会让
  安卓/iOS 的部分场景丢掉查询串，启动即 403 白屏；不写则默认用当前文档 URL，
  sharecode 自然带过去。
- Service Worker 里所有 `cache.match` 都带 `ignoreSearch: true`，
  否则请求上的 `?sharecode=` 会让缓存永远不命中。

**2. Service Worker 只缓存 `res.ok` 的响应。**
上面的 403 返回的是一张正常的 HTML 错误页，HTTP 状态是 403 但 `res.ok` 为 false。
如果无脑 `cache.put`，那张错误页会被永久缓存，App 从此打不开——
这是这类带鉴权的托管地址最容易埋的雷。

**3. 图标用线性 SVG，不用 emoji。**
底部 Tab 一开始用的 📖 和 ▤，在真机上会被系统渲染成彩色贴图，和墨色纸色的调子完全不搭，
且不同手机长得不一样。改成 `stroke: currentColor` 的 SVG 后跟着主题色走。

### 验证过的

`python scripts/check_mobile.py` 一把跑完（本地起服务，或 `--url` 打线上）：

- 三种屏宽（375 / 390 / 430）：铺满屏、无横向溢出、最小热区 44px、无 textarea、
  首屏加载层会消失、1,515 张卡 / 30 篇 823 句 —— 全过。
- 主流程：开一轮 → 选一项 → 答案页（含白话块），**换页 ≤120ms**（实测 2–4ms）—— 过。
- **20 题 → 小结 →「回首页」** —— 这条是用户报过的 bug（`data-act="home"` 当初
  根本没有分支，点了既不报错也不重绘），专门钉一条断言。
- 篇章：目录 30 篇 → 篇详情 98 句整篇原文 → 点句弹层有白话/英译 → 开始刷题出选项 —— 过。
- 篇内题池：滕王阁序 池 49 道 → 两轮各 20 题、**重合 0**（不是同一批）→「整篇一遍」出 49 题 —— 过。
- 配色：正确项 = `--ok` 绿、错选项 = `--bad` 红 —— 过。
  （原来还有一问「尚未揭晓的选中态 ≠ 绿」，点选即换页后这一帧不存在，断言改为盯换页耗时）
- 点词词典：点英译里的词 → 浮卡出现、完全落在机身内、位置在词上方、有发音按钮和音标、
  点空白能收掉 —— 全过。另加两条「只有截图才看得出来」的：
  浮卡淡入已完成（`opacity ≥ .95`）、**背景 alpha ≥ .8**（透明浮卡会把下面的选项透上来，
  但 DOM 断言全绿，第一版就是这么漏的）、释义里没有残留字面量 `\n`。
- 中途退出：答案页有退出按钮 → 弹确认 → 回到首页 —— 全过。
- 发音：联网时尝试真人音，**断网时必须退到系统 TTS**（断言 `window.__say.last`）—— 过。
  注：无头浏览器里 `play()` 常被自动播放策略拦掉，所以本地跑出来总是 `tts`；
  真人音这条链路是单独用 `curl` 验的（有道 `dictvoice` 返回 `200 / audio/mpeg / 10 KB`）。
- 文案与入口：首页没有 `.footnote`、目录说明 ≤30 字且点明灰/黑、`.entry` 是 `<button>` —— 过。
- 本机篇目：`＋`（44 热区）→ 表单三栏 → 空篇名被拦下且人还留在表单 → 存 3 句 →
  目录出现带「本机」标的一篇（31 篇）→ 能为它出 4 选项的句级题 → 删除后回到 30 篇 —— 全过。
- 弹层按钮：改档 →「重点 ▾」、换主题 → `data-theme="dark"` —— 过。
  这两条是补的**静默 bug**：遮罩挂 `data-act="closesheet"`、面板挂
  `onclick="event.stopPropagation()"`，面板把事件拦在冒泡路上，document 上的委托收不到，
  于是改档、换主题、切发音、清除记录、单练这句**全都点不动，而且不报错**。
  现在遮罩关闭改成「判断点的是不是遮罩本身」，内联 `stopPropagation` 全部删掉。

这个脚本做过反向自检：把「回首页」分支删掉、把正确项改回橙色、把白话块删掉，
三处退化都被准确报出（且报的是具体哪个颜色不对，不是笼统的「配色失败」）。

- 线上页面端到端 9 项：数据加载 1,515 张、标题、开始一轮、选项可点、进答案页、
  Service Worker active、缓存 7 条（含 `dict.js`）、无 JS 报错 —— 全过。
- 真断网重载 5 项：CDP `Network.emulateNetworkConditions` 断网后 reload，
  仍能出 1,515 张卡、首页渲染、能开一轮、能进答案页 —— 全过。
